\section{Reproducibility and Source Map}
\label{app:reproducibility}
The code and report sources are available in the
\href{https://github.com/Kautenja/ArhythmeticUnits-Fourier}{Fourier repository}.
The report's modular sources live in \path{docs/whitepaper/}; the submission
exporter expands them
into a standalone TeX file. Typesetting performs no experiments, dependency
fetches, or network requests. From the repository root:
\begin{lstlisting}[language=bash]
python3 docs/whitepaper/tools/comparison_paper.py --check
make -C docs/whitepaper check
make -C docs/whitepaper arxiv
\end{lstlisting}
The outputs are \path{paper.pdf} and \path{fourier-arxiv-source.tar.gz} in
\path{docs/whitepaper/.build/}. The latter is a portable source archive.
After extraction into an empty directory, compile with
\begin{lstlisting}[language=bash]
latexmk -pdf -pdflatex='pdflatex -no-shell-escape %O %S' fourier.tex
\end{lstlisting}
These commands validate and reproduce document assets; they do not repeat
the timing experiment.

\subsection*{Confirmation evidence}
\path{docs/whitepaper/data/comparison-012/} contains the frozen designs,
host records, compressed campaign metadata, all summary/process tables,
numerical coverage, and the measured first-party source. The nominal revision
is \code{12ac3236e332b7d0a01b2d750fa07a0849132341}, with the recorded runner
fix excluding Finder metadata from source inventories. The exact measured
source archive has SHA-256
\begin{quote}\ttfamily\small
\nolinkurl{bd46acd4281fdb6099908dab857351270554d9b93563620356bd3b8833000724}.
\end{quote}
The source, dependency, executable, configuration, and plan identities in each
campaign determine what was measured; the later manuscript revision does not.
Compiler commands and numerical policies are preserved with those identities.

The publication generator reads the immutable committed CSV tables, verifies
their source-manifest hashes, and writes selected LaTeX tables, vector plot
coordinates, numerical macros, and a provenance receipt. Its check mode
rederives those outputs without modifying measurements. Selected workloads
have complete configuration identities; length trends keep all three primary
lengths, and the full grid remains available even where it is not typeset.
Historical results are not merged into these selections.

Individual callback observations, full reports, and portable audit tooling are
preserved in six \emph{local, untracked} bundles identified by
\path{data/comparison-012/bundles.json}. They have not been deposited at a
public archive. A fresh repository clone can check the published tables and
regenerate the selected document assets, but cannot rederive all statistics
from individual observations without those bundles. The local bundle README
gives unpacking and rederivation commands. All five confirmation bundles
passed table rederivation, and both pilot reviews reproduced from their bundle.
Native executables, Rack SDK bytes, and dependency archives are explicitly
omitted from the portable bundles; their measured hashes remain recorded.
Repeating timings requires separately acquiring the recorded dependencies and
preparing a measurement host. Public deposition of the raw bundles is a
remaining dissemination step, not a completed result of this report.

\subsection*{Historical campaigns and implementation}
The original campaign's exact inputs are in
\path{docs/whitepaper/data/source.tar.gz}; its README gives isolated extraction
and reproduction commands. The archive restores historical math-header paths
and the driver hashes in its own metadata. The complete-pipeline prototype
sources and dependency headers are in
\path{docs/whitepaper/data/pipeline/source.tar.gz}. That campaign retains 2880
per-repetition timing summaries and 27 baseline phase observations; it did not
retain individual timed calls. Its README and metadata describe those distinct
methods. Neither dataset measures the current production successor.

The production paths are \path{src/dsp/spectrum_analysis.hpp},
\path{src/SpectrumAnalyzer.cpp}, and \path{src/Spectrogram.cpp}.
\path{src/rack_extensions/display_mailbox.hpp} defines snapshot ownership;
\path{src/rack_extensions/spectrum_coordinates.hpp} maps Fourier's bins.
\path{src/dsp/fft.hpp} supplies the reusable forward and inverse components.
The comparison adapters and fixtures live in \path{benchmark/paper/};
\path{docs/whitepaper/benchmarks/} owns their campaign/report workflow.
These research adapters are not integrated into the Rack modules.
Production test and build commands remain in \path{CONTRIBUTING.md}.
