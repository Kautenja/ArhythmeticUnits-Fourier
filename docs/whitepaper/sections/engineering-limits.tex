\section{Discussion and Limits}
\label{sec:discussion}
\subsection{A practical choice of execution granularity}
Begin with native batch under the required complete-path semantics. If its
per-hop peaks fit the allocated analysis budget and fresh output matters,
immediate execution is a strong choice. If aligned releases consume too much
headroom, test staggering or a native hybrid; shorten its horizon when age
matters. Choose butterfly scheduling when its measured complete-path behavior
meets a requirement the coarser alternatives do not, at acceptable total cost.

This is an empirical design rule rather than a deadline guarantee. The
four-module, one-thread result provides the clearest practical example: the
production path reduces typical block concentration from roughly two-thirds
to one-sixth of the budget relative to vDSP batch. Yet the native hybrid is
competitive in several controlled shapes, and multithreaded Rack changes the
ranking. The implementation contract remains useful across those choices;
performance cannot be inferred from the number of resumable butterflies alone.
Rack's average CPU meter also reflects aggregate cost, so a lower burst can
still appear more expensive to a user.

Publication age is an explicit cost. A 30\,ms hop adds about 1.8 frames of a
60\,Hz display before polling and repaint. That arithmetic does not establish
a perceptual threshold. For latest-frame visualization a UI or worker thread
may be preferable; for exact-hop producer history its capture, queueing,
overflow and ownership policy must be specified. Spectre's history storage
and per-column mailboxes support a different consumer contract from Fourier's
latest curve. These alternatives deserve measurement at equivalent boundaries
before a broader recommendation.

\subsection{What the evidence can establish}
Native layouts, actual module/engine processing and a concurrent consumer
connect the controlled analyzer to its host. Both pilots nevertheless use one
M1 Pro, binary, compiler and local date. This is an early Apple Silicon laptop,
not the original base M1 or a lower performance bound for Apple hardware.
Independent-day, build and architecture replication remains outstanding.

Careful setup and sleep/power checks coexist with residual OS activity.
Snapshots cannot identify the cause of an individual outlier; longer compute
paths may have greater interruption exposure, but that mechanism was not
isolated. Maxima and session ranges retain those observations. Fixed group
order also confounds workload family with time and possible thermal change.

The stream study lacks a separate throughput pass, a matched paced/continuous
cross-over at identical boundaries, core-placement calibration, and a
thread-policy sweep. Four-thread engine workers consume substantial CPU even in the empty
graph, so changes with thread count cannot be attributed solely to parallel
analysis. The host filler set did not locate a saturation threshold.
The extreme module path lacks matched paced native controls. Those are concrete
limits on causal or reliability claims, even though the recorded comparisons
are internally traceable. Headless consumption verifies copy/ownership and
logical age; device underruns, GUI load and repaint are outside its scope.
Native allocator internals remain opaque, and retained unused module storage
precludes a total-memory ranking.

\subsection{Scope of the contribution}
The analytical result bounds credits for a complete dependency-ordered
analyzer. A conditional operation-cost model explains how weights could be
chosen, while measured times test implementations on this host. Cache effects,
unequal unit costs, interrupts and unrelated engine work separate these two
claims. Empirically tuned weights and an unweighted band-cache rebuild are
implementation choices, not a proof of time balance.

Time-distributed transforms and cooperative chains precede this work. The
specific contribution is to join analysis-tail accounting, exact-hop cadence,
input lifetime, cancellation and output ownership with comparisons that expose
placement, kernel and host effects. Sub-FFT native leaves could improve the
tradeoff and remain an important missing granularity. Inverse synthesis and
long-filter convolution require their own bounded preparation and delivery
stages; no new performance claim for those applications follows from this
analysis-only campaign.
