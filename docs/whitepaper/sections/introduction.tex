\section{Introduction}
Spectral analysis shares an audio engine's processing budget even when it
produces no audio output. An analyzer that consumes little CPU time on average
can still concentrate window preparation, transformation, and display-data
processing into a single host callback. Conversely, spreading those operations
can add dispatch cost and delay the spectrum. For interactive audio software,
the relevant objective is therefore a joint constraint on aggregate cost,
processing bursts, and the age of the information delivered to the application.

This paper asks how to schedule complete windowed analysis on an existing
engine thread while making those tradeoffs explicit. A batch FFT is an
appropriate baseline when its call fits the available budget. A worker thread
can move analysis away from that thread when asynchronous delivery is
acceptable. Cooperative execution offers another choice: retain the state of
an unfinished analysis and advance it on successive engine sample calls.
No additional thread is required, but the application must account for all
stages and preserve the selected input until it is consumed.

Making the FFT resumable is insufficient on its own. A butterfly budget can
leave frame-sized packing, reconstruction, and output passes at the boundaries.
Furthermore, restarting as soon as a transform completes can change the frame
interval even when the requested computation horizon is unchanged. These
observations motivate a dependency-ordered sequence for the complete analyzer
and a publication clock independent of early arithmetic completion.
The approach builds on time-distributed transforms and cooperative processing
chains; its contribution is the explicit contract for this windowed analyzer,
not a new FFT factorization.

We specify the work-credit bound, exact publication cadence, input-retention
requirement, cancellation behavior, and ownership of completed output. We also
define comparisons that distinguish distributing a fixed implementation from
choosing a different FFT or processing layout. This distinction matters because
a lower callback tail can coexist with higher total cost, and an optimized
batch implementation can outperform a finely scheduled one. The empirical
question is which workloads justify the additional state and spectrum age,
rather than whether suspension is universally preferable.

The implementation is the shared analyzer in the Fourier spectrum analyzer
and Spectre spectrogram modules for VCV Rack. Fourier processes four independent
channels in SIMD lanes; Spectre uses scalar samples. The design described here
matches production revision \code{785446a5b2f9}, including weighted preparation
and output credits. Each timing campaign identifies its own measured sources;
that implementation description does not transfer historical timings to the
current code. Section~\ref{sec:evaluation} defines the production comparison
protocol. Section~\ref{sec:historical-evidence} summarizes the available
historical evidence, with full methods and results in the appendices. Final
production comparisons remain pending, so performance rankings and operating
recommendations are not conclusions of this revision.
